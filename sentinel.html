Decision model - early access

Sentinel makes the quick calls.

Coding agents spend a long reasoning pass on questions that have short answers: will this patch pass, which file comes first, is it time to run the tests. Sentinel is Ephemerent's decision model, a fast "System One" for those moments. It answers yes or no, picks among named options, or ranks candidates, in about a fifth to a third of a second, and every answer carries a calibrated probability.

Sentinel does not write code or prose. It reads the facts you give it, answers the one question you ask, and tells you how sure it is, so an agent can keep its long thinking for the work that needs it.

What it does

Three kinds of call cover most of the small judgements an agent makes between real steps.

Decide

Yes or no

A direct question about the current state, answered with the probability that the answer is yes.

Will this patch make the failing test pass?yes · p_yes 0.91
Choose

One of several

Name the options and describe each in a line. Sentinel picks one and gives a probability for every option.

Which of these should the agent do next: edit, read, or run?edit · 0.84
Rank

In order

Hand it a list of candidates and get them back best first, each with its share of the probability.

Which fix should we try first?fix the parser 0.78 · fix the test 0.22

Why use it

  • FastA decision comes back in about a fifth to a third of a second, quick enough to ask at every step instead of reasoning the question out at length.
  • CalibratedEvery answer carries a probability, and the probabilities mean what they say: on held-out checks, answers given at 80 % are right about 80 % of the time. Below about 0.7, treat an answer as uncertain and let the agent think it through.
  • Fails fastIf Sentinel is unreachable, the tools return straight away and the agent decides on its own. Sentinel can make an agent quicker; it is built never to make one slower.

Where it works

  • OrrerySentinel runs inside Orrery, where the agent consults it for the quick calls during a run.
  • MCP agentsAdd the Sentinel MCP server to any agent that speaks the Model Context Protocol: Claude Code, OpenCode, Cursor, Codex CLI, Gemini CLI or VS Code. The agent gets three tools, sentinel_decide, sentinel_rank and sentinel_status, with descriptions that tell it when to ask.
  • Function callingFor your own agent loop, register sentinel_decide as a tool in the OpenAI or Anthropic format and forward the call to the API.
  • ShellA small command-line client answers in its exit code, for scripts and shell-driven agents.
  • APITwo HTTP endpoints on api.ephemerent.com, with the same key as the Arbiter API.

API quickstart

Sentinel uses the API key from your account page, sent as a bearer token. Give it the facts in state (code, a diff, an error message), ask one question, and add options when there are more than two answers.

POST/v1/sentinel/decideA yes/no answer with p_yes, or with options, the chosen option, its confidence and a probability for each.
POST/v1/sentinel/rankCandidates in order, best first, each with its probability.
GET/v1/sentinel/statusWhether Sentinel is up right now.
curl https://api.ephemerent.com/v1/sentinel/decide \
  -H "Authorization: Bearer $ARBITER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "state": "test_parse_date fails: ValueError on \"2026-09-26T10:00Z\". The patch adds a branch for a trailing Z in parse_date.",
    "question": "Will this patch make the failing test pass?"
  }'

# {"answer": "yes", "p_yes": 0.91, "model": "sentinel-1"}
# Python (pip install requests)

r = requests.post(
    "https://api.ephemerent.com/v1/sentinel/decide",
    headers={"Authorization": f"Bearer {os.environ['ARBITER_API_KEY']}"},
    json={
        "state": diff + "\n\n" + test_output,
        "question": "Which of these should the agent do next?",
        "options": {
            "edit": "apply the fix to parse_date",
            "read": "open the caller before changing anything",
            "run": "run the test suite as it is",
        },
    },
    timeout=8,

if r.status_code == 503:
    decision = None          # Sentinel is offline: decide without it

    decision = r.json()

    #  "p": {"edit": 0.84, "read": 0.12, "run": 0.04}, "model": "sentinel-1"}

For your own agent loop, this is the tool definition to register. Forward its arguments to /v1/sentinel/decide and return the answer to the model.

{
  "name": "sentinel_decide",
  "description": "Ask Sentinel for a fast, calibrated judgement on a short question about the current task. Returns an answer with a probability; below 0.7, treat the answer as uncertain and reason it through.",
  "parameters": {
    "type": "object",
    "properties": {
      "state":    { "type": "string", "description": "The facts the decision depends on: code, a diff, error output." },
      "question": { "type": "string", "description": "One question with a short answer." },
      "options":  { "type": "object", "additionalProperties": { "type": "string" },
                    "description": "Named options, each with a one-line description. Omit for a yes/no question." }
    },
    "required": ["state", "question"]
  }
}

Limits and pricing

Each decision costs a fraction of a cent, metered in the same compute credits as the rest of the API and drawn from the same balance. sentinel-1 is listed in /v1/models, but it is not a chat model: sending it to /chat/completions returns 400. When Sentinel is offline the API answers 503 with a Retry-After header; clients should carry on without it rather than wait.

An honest note

Sentinel is in early access. Capacity is limited, and availability, latency and pricing can change. Treat it as a quick second opinion, not ground truth: the probability tells you how much weight an answer deserves, and a low one is a reason to look closer. You remain responsible for what your agent runs and ships.
